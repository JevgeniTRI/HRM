# HRM · People & Skills

Локальная система управления персоналом и навыками на **Python + FastAPI, React + TypeScript и SQLite**.

Главная страница использует светлый фон, округлые белые карточки, тонкие границы, свободные отступы и спокойные таблицы по мотивам исходного рисунка. Основная навигация расположена вертикально слева; на мобильном экране она открывается кнопкой меню.

## Что работает

- Главная: сводные показатели, распределение по подразделениям, последние события, обзор навыков и новые сотрудники.
- Сотрудники: создание, редактирование, удаление, профиль с навыками, поиск кириллицей, фильтры, пагинация, CSV-экспорт с учётом фильтров.
- Подразделения и каталог навыков: создание, редактирование и удаление с защитой связанных данных.
- Оценки: текущий уровень 0–5, индивидуальный целевой уровень 1–5, отдельное состояние «Не оценён».
- Сертификаты: несколько документов под каждым навыком сотрудника, загрузка из карточки сотрудника и окна оценки навыка, просмотр в новой вкладке, скачивание и удаление. Общий раздел сертификатов в карточке сотрудника группирует документы по навыкам.
- Матрица навыков: поиск, фильтры подразделения/статуса/категории, редактирование оценок из ячейки.
- Kanban-доска задач и обучения: **To Do → In Progress → Done**, перетаскивание и смена статуса из карточки, поиск и фильтры типа/источника/формата/подразделения, несколько подразделений в одной задаче.
- Карточки обучения: внутреннее/внешнее, индивидуальное/групповое, длительность и число участников, человекочасы, общая стоимость с валютой и срок. Пример: **1,5 часа × 10 человек = 15 человекочасов**.
- Миграции Alembic, валидация запросов, транзакции, история изменений, ошибки загрузки, пустые состояния и доступные модальные окна.
- Вход по логину и паролю, четыре роли, личная карточка-резюме, назначение исполнителей задач и управление аккаунтами администратором.

## Быстрый запуск на Windows

Требуются Python 3.12–3.14, Node.js **22.18+** (или 24+) и [uv](https://docs.astral.sh/uv/getting-started/installation/). Проверено на Python 3.14 и Node.js 25.1.

Из корня проекта:

```powershell
.\start.ps1 -Demo
```

Скрипт устанавливает зависимости по lock-файлам, применяет миграции, запускает backend в фоне и frontend в текущем терминале. `-Demo` добавляет 12 вымышленных сотрудников, 4 подразделения и 8 навыков **только в пустую кадровую базу**, а также 6 примеров карточек **только на пустую доску задач**. Для пустой системы запускайте без `-Demo`. Повторный запуск сохраняет данные.

Если в базе ещё нет аккаунтов, при первом запуске создаётся `admin` со случайным паролем, который показывается в терминале один раз. Сохраните его и после входа измените в разделе «Безопасность». Повторные запуски не меняют аккаунты и пароли. При ручном запуске после миграций выполните `.\.venv\Scripts\python.exe -m app.auth_bootstrap` из backend.

| `admin` | Администратор | Все подразделения |
| `power_user` | Пользователь с повышенными правами | Мария Козлова, HR и администрация |
| `manager` | Руководитель | Александр Соколов, Разработка |

Начальный пароль всех четырёх аккаунтов — **`123`**. Каждый пользователь может изменить его в разделе «Безопасность»; для нового пароля предусмотрено 12–128 символов. Пароли в БД хранятся в виде хешей. Отдельные новые базы по-прежнему получают случайный пароль администратора.

Файлы сертификатов хранятся отдельно в `media/certificates`; в текущем снимке сертификатов нет. В репозиторий не включаются `.env`, установленные зависимости, кеши, журналы и временные тестовые данные.

## Роли и доступ

| Роль | Возможности |
| --- | --- |
| Администратор | Все вкладки, отделы и данные; создание аккаунтов, назначение ролей, отключение доступа и сброс паролей. |
| Пользователь с повышенными правами | Управление сотрудниками, задачами и справочниками всех отделов. Управление аккаунтами недоступно. |
| Руководитель | Личная карточка, сотрудники и задачи своего отдела. Может редактировать сотрудников, включая других руководителей этого отдела. Перевод в другой отдел, создание/удаление сотрудников и изменение общих справочников доступны глобальным ролям. |
| Сотрудник | Только собственная карточка-резюме, её навыки и сертификаты, а также назначенные ему задачи. Может редактировать резюме, создавать свои задачи и менять их содержание/статус. Должность, статус занятости, дата приёма, отдел и переназначение задач защищены. |

Администратор создаёт сначала карточку сотрудника, затем аккаунт в разделе «Аккаунты и доступ». Для всех ролей, кроме администратора, привязка к сотруднику обязательна; одному сотруднику соответствует один аккаунт. Отдел руководителя определяется его карточкой. При переводе сотрудника права пересчитываются на следующем запросе.

У задачи можно выбрать исполнителя. Старые задачи сохраняются без исполнителя и остаются доступны глобальным ролям; руководителю доступны неназначенные задачи только его отдела. Сотруднику задачи отдела автоматически не открываются: нужен явный исполнитель. Общие задачи нескольких отделов управляются глобальными ролями; назначенный сотрудник видит свою задачу.

Проверки выполняются сервером, включая прямые URL, JSON, CSV, статистику и файлы сертификатов. Вход хранится в HttpOnly/SameSite cookie; в БД сохраняются хеши паролей и токенов сеансов. Сеанс действует 12 часов. Выход, смена/сброс пароля и изменение аккаунта отзывают соответствующие сеансы. Новые пароли — 12–128 символов. Публичной регистрации нет; начальные данные для включённого снимка перечислены выше.

Интерфейс: [http://127.0.0.1:5173](http://127.0.0.1:5173). Документация API: [http://127.0.0.1:8000/api/docs](http://127.0.0.1:8000/api/docs). Остановка — Ctrl+C в терминале запуска; скрипт завершает запущенный им backend. Оба сервера привязаны к loopback.

Если политика PowerShell запрещает выполнение локального скрипта, используйте ручной запуск ниже. Не требуется менять системную политику выполнения.

## Ручной запуск

Первый терминал:

```powershell
cd backend
uv sync --locked --cache-dir ..\artifacts\uv-cache
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m app.auth_bootstrap
# Необязательно, только для демонстрации:
.\.venv\Scripts\python.exe -m app.seed
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Второй терминал:

```powershell
cd frontend
npm ci
npm run dev
```

Ручной запуск на Linux/macOS аналогичен, но вместо `.venv\Scripts\python.exe` используйте `.venv/bin/python`. Скрипт `start.ps1` и команда backend в настройках Playwright предназначены для Windows; frontend и Python-код не привязаны к Windows.

SQLite-файл хранится в `backend/hrm.db`. Чтобы настроить БД и CORS, скопируйте `backend/.env.example` в `backend/.env`. Относительный путь БД считается от рабочей папки backend. Dev-сервер Vite проксирует `/api` на backend. Поле `API_PROXY_TARGET` в окружении позволяет изменить цель dev-прокси; для preview по умолчанию также используется порт 8000.

API проверяет `Host` и браузерный `Origin`. По умолчанию разрешены loopback-адреса, интерфейс на портах 5173/4173 и документация API на 8000. Для другого порта добавьте точный адрес интерфейса в `HRM_CORS_ORIGINS`; для другого имени сервера настройте `HRM_ALLOWED_HOSTS`. Wildcard в Origin запрещён. Общий предел тела запроса — 11 МБ, предел одного сертификата — 10 МБ. Эти ограничения не заменяют авторизацию.

Доска доступна по адресу [http://127.0.0.1:5173/tasks](http://127.0.0.1:5173/tasks), раздел «Задачи и обучение» в меню. Для добавления примеров отдельно: `cd backend`, затем `.\.venv\Scripts\python.exe -m app.tasks.seed`. При наличии задач команда ничего не добавляет.

Человекочасы рассчитывает backend; предварительный расчёт в форме использует тот же серверный алгоритм. Стоимость — общая, не на человека; 0 означает бесплатно, пустое поле — неизвестна. Сводка считает все подходящие под фильтры задачи по всем статусам, а суммы в разных валютах показывает отдельно. Колонки загружают карточки порциями по 20 с кнопкой «Показать ещё»; последняя изменённая карточка находится сверху. На телефоне можно менять статус через список в карточке.

## Проверки

Сертификаты хранятся в `media/certificates` в корне проекта. Каталог создаётся автоматически при загрузке; путь не зависит от рабочей директории и настраивается через `HRM_MEDIA_ROOT`. Поддерживаются PDF, PNG, JPG и WebP размером до 10 МБ. Файлы получают уникальные имена; исходное имя сохраняется для скачивания. При удалении сертификата, навыка сотрудника или самого сотрудника удаляются и соответствующие файлы. Для резервной копии сохраняйте вместе БД и каталог `media`.

После обновления выполните `uv sync --locked`, `python -m alembic upgrade head` и `python -m app.auth_bootstrap` в backend (или запустите `start.ps1`, который делает это автоматически). Сертификаты наследуют права карточки сотрудника; прямое скачивание также требует действующего сеанса.

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest --basetemp=..\artifacts\pytest-temp -q
.\.venv\Scripts\ruff.exe check app migrations tests
.\.venv\Scripts\ruff.exe format --check app migrations tests
.\.venv\Scripts\python.exe -m alembic check
```

```powershell
cd frontend
npm run build
npm run format:check
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location).Path '..\artifacts\pw-browsers'
npx playwright install chromium
npm run test:e2e
```

Backend-тесты создают отдельную SQLite-БД и применяют реальные миграции. Браузерные тесты запускают отдельный API на 8001 и frontend на 5174 с временной демонстрационной БД; основная `backend/hrm.db` не изменяется. Порты 8001 и 5174 должны быть свободны. Скриншоты сохраняются в `artifacts/dashboard-desktop.png`, `artifacts/dashboard-mobile.png`, `artifacts/kanban-desktop.png` и `artifacts/kanban-mobile.png`.

Сборка frontend находится в `frontend/dist`. `npm run preview` позволяет проверить её локально; для эксплуатации нужно отдельно настроить сервер статических файлов, fallback маршрутов React и прокси `/api`.

## Архитектура и границы первого этапа

Подробности — в [docs/architecture.md](docs/architecture.md): границы модулей, связи данных, определения метрик и дальнейшее развитие.

Бизнес-логика всех модулей сосредоточена в `backend/app/services/`, с отдельными файлами для операций и общих правил. Маршруты оформляют HTTP-ответы, frontend отображает серверные расчёты. Результаты проверки безопасности и оставшиеся ограничения — в [docs/security-review.md](docs/security-review.md).

Система по умолчанию запускается локально. Для размещения в общей сети настройте HTTPS, `HRM_COOKIE_SECURE=true`, точные `HRM_CORS_ORIGINS` и `HRM_ALLOWED_HOSTS`, защиту резервных копий и ограничения нагрузки на прокси. Для небраузерных клиентов нужны cookie сеанса и заголовок `X-HRM-Request: 1` на изменяющих запросах, включая вход. Ограничение попыток входа действует на IP в одном процессе (10 неуспешных попыток за минуту и 30 за 15 минут); при нескольких процессах нужен общий лимитер. SQLite не рассчитана на большую конкурентную нагрузку записи; при таком росте предусмотрено развитие в сторону PostgreSQL.

Официальная документация используемых подходов: [FastAPI — SQL databases](https://fastapi.tiangolo.com/tutorial/sql-databases/), [SQLAlchemy — SQLite](https://docs.sqlalchemy.org/en/20/dialects/sqlite.html), [Vite](https://vite.dev/guide/).

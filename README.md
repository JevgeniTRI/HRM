# HRM · People & Skills

Локальная система управления персоналом и навыками на **Python + FastAPI, React + TypeScript и SQLite**.

Главная страница использует светлый фон, округлые белые карточки, тонкие границы, свободные отступы и спокойные таблицы по мотивам исходного рисунка. Основная навигация расположена вертикально слева; на мобильном экране она открывается кнопкой меню.

## Что работает

- Главная: сводные показатели, распределение по подразделениям, последние события, обзор навыков и новые сотрудники.
- Сотрудники: создание, редактирование, удаление, профиль с навыками, поиск кириллицей, фильтры, пагинация, CSV-экспорт с учётом фильтров.
- Подразделения и каталог навыков: создание, редактирование и удаление с защитой связанных данных.
- Аккаунты и доступ: мгновенный поиск по имени, фамилии или логину без Enter; ФИО в ссылках на карточки, счётчик результатов и очистка поиска. Регистр и различие «е»/«ё» не мешают поиску.
- Оценки: индивидуальная шкала каждого навыка — числовой диапазон в пределах 0–10 или буквенный A–Z, отдельные название и описание каждого уровня, отдельное состояние «Не оценён». Администратор и power_user настраивают шкалу; текущая оценка и цель используют её в карточках, матрице и сводке.
- Сертификаты: несколько документов под каждым навыком сотрудника, загрузка из карточки сотрудника и окна оценки навыка, просмотр в новой вкладке, скачивание и удаление. Общий раздел сертификатов в карточке сотрудника группирует документы по навыкам.
- Матрица навыков: поиск, фильтры подразделения/статуса/категории, редактирование оценок из ячейки.
- Kanban-доска задач и обучения: **To Do → In Progress → Done**, перетаскивание и смена статуса из карточки, поиск и фильтры типа/источника/формата/подразделения, несколько подразделений в одной задаче.
- Календарь обучений: диаграмма Ганта на весь выбранный год с масштабом по месяцам и неделям, начало и окончание обучения, календарный период и длительность в часах; сводка по нажатию на полосу, поиск и фильтр подразделения. Обучения без дат доступны отдельным списком.
- Карточки обучения: внутреннее/внешнее, индивидуальное/групповое, длительность и число участников, человекочасы, общая стоимость с валютой и срок. Пример: **1,5 часа × 10 человек = 15 человекочасов**.
- Миграции Alembic, валидация запросов, транзакции, история изменений, ошибки загрузки, пустые состояния и доступные модальные окна.
- Вход по логину и паролю, четыре роли, личная карточка-резюме, назначение исполнителей задач и управление аккаунтами администратором.

## Быстрый запуск на Windows

Требуются Python 3.12–3.14, Node.js **22.18+** (или 24+) и [uv](https://docs.astral.sh/uv/getting-started/installation/). Проверено на Python 3.14 и Node.js 25.1.

Из корня проекта:

```powershell
.\start.ps1 -Demo
```

Скрипт устанавливает зависимости по lock-файлам, применяет миграции, запускает backend в фоне и frontend в текущем терминале. `-Demo` добавляет 12 вымышленных сотрудников, 4 подразделения и 8 навыков **только в пустую кадровую базу**, а также 6 примеров карточек **только на пустую доску задач**. Для пустой системы запускайте без `-Demo`. Повторный запуск сохраняет данные.

Если в базе ещё нет аккаунтов, при первом запуске создаётся `admin` со случайным паролем, который показывается в терминале один раз. Сохраните его и после входа измените в разделе «Безопасность». Повторные запуски не меняют аккаунты и пароли. При ручном запуске после миграций выполните `.\.venv\Scripts\python.exe -m app.auth_bootstrap` из backend.

## Роли и доступ

| Роль | Возможности |
| --- | --- |
| Администратор | Все вкладки, отделы и данные; создание аккаунтов, назначение ролей, отключение доступа и сброс паролей. |
| Пользователь с повышенными правами | Управление сотрудниками, задачами и справочниками всех отделов. Управление аккаунтами недоступно. |
| Руководитель | Личная карточка и своя ветка подчинения только в своём отделе, включая промежуточных руководителей. Может редактировать карточки своей команды и управлять назначенными ей задачами. Сотрудники других отделов и соседних веток недоступны. Перевод между отделами, изменение подчинённости, создание/удаление сотрудников и изменение общих справочников доступны глобальным ролям. |
| Сотрудник | Только собственная карточка-резюме, её навыки и сертификаты, а также назначенные ему задачи. Может редактировать резюме, создавать свои задачи и менять их содержание/статус. Должность, статус занятости, дата приёма, отдел и переназначение задач защищены. |

Администратор создаёт сначала карточку сотрудника, затем аккаунт в разделе «Аккаунты и доступ». Для всех ролей, кроме администратора, привязка к сотруднику обязательна; одному сотруднику соответствует один аккаунт.

В карточке сотрудника блок «Руководитель и подчинённые» показывает роль в отделе, непосредственного начальника и прямых подчинённых. Администратор и power_user открывают «Настроить подчинённость» и выбирают «Руководитель отдела», «Промежуточный руководитель» или «Подчинённый (сотрудник)». Здесь же можно выбрать прямых подчинённых, в том числе нескольких сразу. Все участники должны находиться в одном отделе; поиск начальника и подчинённых ограничен этим отделом. Промежуточных руководителей может быть несколько по цепочке.

Фактический статус определяется подчинёнными: без них пользователь — сотрудник; с подчинёнными и собственным начальником — промежуточный руководитель; с подчинёнными без начальника — руководитель отдела. Поэтому сохранение варианта «Руководитель отдела» без подчинённых оставляет фактический статус «Сотрудник». Назначение первого подчинённого автоматически повышает статус, переназначение или удаление последнего — снимает его. Статус не даёт и не снимает глобальные права администратора и power_user. Роли обычных аккаунтов синхронизируются автоматически, даже если в запросе управления аккаунтом указано другое значение «Сотрудник» / «Руководитель»; после смены роли нужно войти заново. Новые связи пересчитывают доступ на следующем запросе.

Нельзя назначить себя, создать цикл или удалить руководителя с подчинёнными. Чтобы убрать текущего подчинённого, назначьте ему нового начальника в его карточке. При переводе сотрудника в другой отдел прежний начальник снимается; перед переводом руководителя необходимо переназначить его команду. Миграция 0011 сохраняет профили и допустимые цепочки, снимает старые связи между разными отделами и пересчитывает статусы по реальным подчинённым. Новые связи по совпадению отдела не угадываются: их задаёт администратор или power_user. Новые команды, создаваемые командой `app.seed_expansion`, сразу получают явные связи с руководителем.

У задачи можно выбрать исполнителя. Старые задачи сохраняются без исполнителя и доступны глобальным ролям. Руководитель выбирает исполнителя из своей ветки подчинения в своём отделе. Сотруднику нужен явный исполнитель — он сам. Эти же ограничения действуют в календаре обучений, сводках, матрице, CSV-экспорте, файлах сертификатов и по прямым ссылкам. Рекурсивный поиск не пересекает границы отдела, даже если в старых данных осталась некорректная связь.

Проверки выполняются сервером, включая прямые URL, JSON, CSV, статистику и файлы сертификатов. Вход хранится в HttpOnly/SameSite cookie; в БД сохраняются хеши паролей и токенов сеансов. Сеанс действует 12 часов. Выход, смена/сброс пароля и изменение аккаунта отзывают соответствующие сеансы. Новые пароли — 12–128 символов. Публичной регистрации нет; начальные данные для включённого снимка перечислены выше.

Интерфейс: [http://127.0.0.1:5173](http://127.0.0.1:5173). Документация API: [http://127.0.0.1:8000/api/docs](http://127.0.0.1:8000/api/docs). Остановка — Ctrl+C в терминале запуска; скрипт завершает запущенный им backend. Оба сервера привязаны к loopback.

Если политика PowerShell запрещает выполнение локального скрипта, используйте ручной запуск ниже. Не требуется менять системную политику выполнения.

## Ручной запуск

Первый терминал:

```powershell
cd backend
uv sync --locked --cache-dir ..\artifacts\uv-cache
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m app.auth_bootstrap
# Необязательно, только для демонстрации:
.\.venv\Scripts\python.exe -m app.seed
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Второй терминал:

```powershell
cd frontend
npm ci
npm run dev
```

Ручной запуск на Linux/macOS аналогичен, но вместо `.venv\Scripts\python.exe` используйте `.venv/bin/python`. Скрипт `start.ps1` и команда backend в настройках Playwright предназначены для Windows; frontend и Python-код не привязаны к Windows.

SQLite-файл хранится в `backend/hrm.db`. Чтобы настроить БД и CORS, скопируйте `backend/.env.example` в `backend/.env`. Относительный путь БД считается от рабочей папки backend. Dev-сервер Vite проксирует `/api` на backend. Поле `API_PROXY_TARGET` в окружении позволяет изменить цель dev-прокси; для preview по умолчанию также используется порт 8000.

API проверяет `Host` и браузерный `Origin`. По умолчанию разрешены loopback-адреса, интерфейс на портах 5173/4173 и документация API на 8000. Для другого порта добавьте точный адрес интерфейса в `HRM_CORS_ORIGINS`; для другого имени сервера настройте `HRM_ALLOWED_HOSTS`. Wildcard в Origin запрещён. Общий предел тела запроса — 16 МБ, предел одного сертификата — 15 МБ. Эти ограничения не заменяют авторизацию.

Доска доступна по адресу [http://127.0.0.1:5173/tasks](http://127.0.0.1:5173/tasks), раздел «Задачи и обучение» в меню. Для добавления примеров отдельно: `cd backend`, затем `.\.venv\Scripts\python.exe -m app.tasks.seed`. При наличии задач команда ничего не добавляет.

Календарь доступен по адресу [http://127.0.0.1:5173/training-calendar](http://127.0.0.1:5173/training-calendar), раздел «Календарь обучений». Диаграмма прокручивается по всему выбранному году, от 1 января до 31 декабря, включая месяцы без обучений. Заголовок и поле даты показывают начало видимой части шкалы. Выбор даты перемещает календарь к нужному дню; смена года загружает его обучения. Масштаб «Неделя» увеличивает детализацию, сохраняя прокрутку по году. В карточке обучения укажите обе даты: «Начало обучения» и «Окончание обучения». Период включает последний день; учебные часы указываются отдельно и не вычисляются из календарных дней. Срок задачи сохраняется независимо от периода обучения. Существующие обучения без дат не получают вымышленные даты: они остаются в списке «Без назначенных дат» с кнопкой назначения периода. Доступ соответствует правам доски задач.

Человекочасы рассчитывает backend; предварительный расчёт в форме использует тот же серверный алгоритм. Стоимость — общая, не на человека; 0 означает бесплатно, пустое поле — неизвестна. Сводка считает все подходящие под фильтры задачи по всем статусам, а суммы в разных валютах показывает отдельно. Колонки загружают карточки порциями по 20 с кнопкой «Показать ещё»; последняя изменённая карточка находится сверху. На телефоне можно менять статус через список в карточке.

В разделе «Навыки» откройте «Редактировать навык»: здесь доступны тип шкалы, начало и конец диапазона и два отдельных поля для каждого уровня: название (до 100 символов) и описание требований (до 1000 символов). Можно выбрать, например, 0–10, 2–7, A–Z или C–H. Буквенные уровни возрастают от A к Z. Текущая оценка и индивидуальная цель выбираются только из диапазона навыка; «Не оценён» не совпадает с уровнем 0 или A. В карточке сотрудника показывается название уровня, например «2 — Базовый». Нажатие на текущее или целевое название открывает все уровни этой компетенции с описаниями, отметками текущей оценки и цели. Этот просмотр доступен в собственной карточке и обычному сотруднику. Описания также доступны при выставлении оценки и в подсказках матрицы.

Существующие навыки при обновлении сохраняют свой диапазон, оценки, цели, общее описание и ранее введённые требования к уровням. Новые навыки в интерфейсе по умолчанию получают шкалу 0–10. Смена типа шкалы сохраняет позиции оценок: 0 → A, 1 → B и далее. Диапазон нельзя сузить, если он исключает существующую оценку или цель: сначала измените оценки сотрудников или расширьте диапазон. Настройка шкал через API защищена теми же правами администратора и power_user.

## Команды и массовое назначение

Раздел «Команды» доступен администратору, power_user и руководителям (в пределах своей ветки и отдела). Управление доступно только администратору и power_user. В карточке сотрудника показывается его команда. Руководитель команды учитывается отдельно от её участников; сотрудник может руководить одной командой и одновременно входить в команду вышестоящего руководителя.

1. Создайте команду: название, уникальный код (например, `DEV-01`), отдел, руководитель и вышестоящий руководитель. Начальников можно назначить позже. Текущие прямые подчинённые выбранного руководителя автоматически войдут в команду; если вышестоящий начальник не выбран, сохраняется текущий. Существующие связи при миграции не меняются и команды не создаются по предположениям.
2. В карточке команды нажмите «Добавить сотрудников». Поиск работает по имени, email и должности; «Выбрать всех найденных» выбирает все страницы результатов. Можно назначить сразу 50 или больше сотрудников. По умолчанию показаны сотрудники без команды; снятие фильтра позволяет массово перевести людей из других команд того же отдела.
3. Для замены начальника нажмите «Заменить руководителя» и выберите нового сотрудника. Участники и вложенные руководители перейдут автоматически, вышестоящее подчинение сохранится. Прежний руководитель освобождается от команды и непосредственного начальника; его карточка, навыки, сертификаты и личные задачи сохраняются. Назначение сотрудника из состава команды повышает его до руководителя, поэтому число остальных участников уменьшается на одного. Руководителя другой команды сначала нужно освободить от неё.

Пустую команду можно удалить. При выводе участника он остаётся без команды и непосредственного начальника; для перевода между командами удобнее сразу назначить его в целевую команду. Смена подчинённости через карточку сотрудника также синхронизирует команды и статусы. Перевод в другой отдел снимает членство в команде; руководителей и вышестоящих начальников сначала нужно заменить в связанных командах. Изоляция отделов, защита от циклов и автоматический статус сотрудника без подчинённых сохраняются. Устаревшая форма не может перезаписать изменённую другим пользователем команду.

В разделе «Команды» кнопка «Импорт Excel / CSV» принимает `.xlsx` (первый лист) и `.csv` (UTF-8 или Windows-1251, разделители `;`, `,` или табуляция), до 5 МБ и 10 000 строк. Для XLSX нужно заменить формулы значениями. В окне есть шаблон CSV, который открывается в Excel.

| Столбец | Назначение |
| --- | --- |
| `email` | Обязателен. По нему определяется существующий сотрудник. Повторы внутри файла считаются ошибкой. |
| `team_code` | Обязателен. Код заранее созданной команды. |
| `department` | Необязательная проверка: название или ID отдела должны совпасть с командой. |
| `first_name`, `last_name`, `position`, `hired_at` | Обязательны для новой карточки: имя, фамилия, должность, дата приёма `ГГГГ-ММ-ДД`. |

Например: `ivan@example.com;DEV-01;Разработка;Иван;Петров;Инженер;2026-01-15` под заголовками скачанного шаблона. Для существующих сотрудников достаточно двух столбцов `email;team_code`: личные данные не перезаписываются. Новые карточки создаются без аккаунта для входа; доступ настраивается отдельно.

«Проверить файл» показывает количество новых карточек и назначений, первые 100 строк и ошибки с номерами строк. Проверка ничего не сохраняет. «Подтвердить импорт» повторяет проверки и сохраняет весь файл одной транзакцией. При ошибках, цикле или изменении данных после предварительной проверки импорт не выполняется. Проверен сценарий: 12 команд по 50 сотрудников, один файл на 600 человек, последующая замена руководителя с сохранением состава.

## Общий импорт и интеграции

Раздел «Импорт и интеграции» (`/imports`) позволяет администратору и power_user загружать отделы, сотрудников, команды и навыки из Excel/CSV с предварительной проверкой и журналом результатов. API принимает JSON по отдельным отзываемым ключам с ограничением типов данных и защитой повторных запросов. Для SAP требуется настроить отправку данных по этому контракту. Форматы, примеры и правила обновления: [docs/integrations.md](docs/integrations.md).

## Проверки

Сертификаты хранятся в `media/certificates` в корне проекта. Каталог создаётся автоматически при загрузке; путь не зависит от рабочей директории и настраивается через `HRM_MEDIA_ROOT`. Поддерживаются PDF, PNG, JPG и WebP размером до 15 МБ. Файлы получают уникальные имена; исходное имя сохраняется для скачивания. При удалении сертификата, навыка сотрудника или самого сотрудника удаляются и соответствующие файлы. Для резервной копии сохраняйте вместе БД и каталог `media`.

После обновления выполните `uv sync --locked`, `python -m alembic upgrade head` и `python -m app.auth_bootstrap` в backend (или запустите `start.ps1`, который делает это автоматически). Сертификаты наследуют права карточки сотрудника; прямое скачивание также требует действующего сеанса.

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest --basetemp=..\artifacts\pytest-temp -q
.\.venv\Scripts\ruff.exe check app migrations tests
.\.venv\Scripts\ruff.exe format --check app migrations tests
.\.venv\Scripts\python.exe -m alembic check
```

```powershell
cd frontend
npm run build
npm run format:check
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location).Path '..\artifacts\pw-browsers'
npx playwright install chromium
npm run test:e2e
```

Backend-тесты создают отдельную SQLite-БД и применяют реальные миграции. Браузерные тесты запускают отдельный API на 8001 и frontend на 5174 с временной демонстрационной БД; основная `backend/hrm.db` не изменяется. Порты 8001 и 5174 должны быть свободны. Скриншоты сохраняются в `artifacts/dashboard-desktop.png`, `artifacts/dashboard-mobile.png`, `artifacts/kanban-desktop.png` и `artifacts/kanban-mobile.png`.

Сборка frontend находится в `frontend/dist`. `npm run preview` позволяет проверить её локально; для эксплуатации нужно отдельно настроить сервер статических файлов, fallback маршрутов React и прокси `/api`.

## Архитектура и границы первого этапа

Подробности — в [docs/architecture.md](docs/architecture.md): границы модулей, связи данных, определения метрик и дальнейшее развитие.

Бизнес-логика всех модулей сосредоточена в `backend/app/services/`, с отдельными файлами для операций и общих правил. Маршруты оформляют HTTP-ответы, frontend отображает серверные расчёты. Результаты проверки безопасности и оставшиеся ограничения — в [docs/security-review.md](docs/security-review.md).

Система по умолчанию запускается локально. Для размещения в общей сети настройте HTTPS, `HRM_COOKIE_SECURE=true`, точные `HRM_CORS_ORIGINS` и `HRM_ALLOWED_HOSTS`, защиту резервных копий и ограничения нагрузки на прокси. Для небраузерных клиентов нужны cookie сеанса и заголовок `X-HRM-Request: 1` на изменяющих запросах, включая вход. Ограничение попыток входа действует на IP в одном процессе (10 неуспешных попыток за минуту и 30 за 15 минут); при нескольких процессах нужен общий лимитер. SQLite не рассчитана на большую конкурентную нагрузку записи; при таком росте предусмотрено развитие в сторону PostgreSQL.

Официальная документация используемых подходов: [FastAPI — SQL databases](https://fastapi.tiangolo.com/tutorial/sql-databases/), [SQLAlchemy — SQLite](https://docs.sqlalchemy.org/en/20/dialects/sqlite.html), [Vite](https://vite.dev/guide/).

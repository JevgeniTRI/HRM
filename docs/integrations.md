# Импорт и интеграции

Раздел `/imports` доступен администратору и `power_user`. Он поддерживает отделы (`departments`), сотрудников (`employees`), команды (`teams`) и навыки (`skills`). Один пакет может содержать несколько типов данных, включая ссылки на другие записи того же пакета. Импорт сохраняется целиком; ошибка отменяет весь пакет.

## Excel / CSV

Скачайте шаблон, выберите источник, загрузите файл и нажмите «Проверить файл». Проверка показывает счётчики, первые 100 записей и ошибки, ничего не сохраняя. После успешной проверки нажмите «Импортировать данные». Если данные изменились, нужна повторная проверка. Сохраняйте одно имя источника при повторных загрузках.

Excel содержит четыре листа: `departments`, `employees`, `teams`, `skills`. Неиспользуемые листы можно оставить с заголовками. CSV содержит общий столбец `entity` с типом каждой строки. Поддерживаются UTF-8 и Windows-1251, разделитель `;`, `,` или табуляция. Лимиты: файл до 5 МиБ, суммарно до 10 000 строк данных, распакованный XLSX до 30 МиБ. Формулы нужно заменить значениями. Даты — Excel либо `ГГГГ-ММ-ДД`. Внешние ID храните как текст, чтобы сохранить начальные нули.

| Сущность | Обязательные поля новой записи | Дополнительные поля |
| --- | --- | --- |
| departments | external_id, name | description |
| employees | external_id, first_name, last_name, email, position, hired_at, department_external_id | status, team_external_id, manager_external_id, about, experience, education |
| teams | external_id, name, code, department_external_id | manager_external_id, supervisor_external_id |
| skills | external_id, name, category | description |

Статусы: `active`, `probation`, `leave`, `inactive`, по умолчанию `active`. `manager_external_id` сотрудника ссылается на его начальника. Для команды это её начальник, а `supervisor_external_id` — вышестоящий руководитель. Все ссылки задаются через внешние ID того же источника. Старый импорт `email;team_code` из раздела «Команды» продолжает работать для заранее созданных команд.

## API для SAP и других систем

Реализован входящий HTTP JSON API. Для конкретной SAP-инсталляции нужно настроить преобразование полей и отправку пакетов, например на интеграционной платформе. Автоматическое подключение к SAP без настройки отправителя не выполняется.

Администратор создаёт ключ во вкладке «API и ключи»: название, источник, разрешённые типы данных и необязательная дата окончания. Секрет показывается один раз; в БД хранится SHA-256. Ключ можно отозвать. Он действует только для интеграционных маршрутов и не предоставляет доступ к аккаунтам и обычным API приложения. Cookie пользователя не подходит для интеграционных маршрутов.

Передавайте `Authorization: Bearer <ключ>` и `Content-Type: application/json`. Заголовок `X-HRM-Request` и cookie не нужны. Используйте HTTPS при развёртывании; имя сервера должно входить в `HRM_ALLOWED_HOSTS`. Лимит тела запроса — 16 МиБ; суммарно от 1 до 10 000 записей в пакете.

- `POST /api/integrations/validate` — предварительная проверка без сохранения. Ответ 200: `errors`, `error_count`, `counts`, `records` (первые 100), `fingerprint`.
- `POST /api/integrations/imports` — создание/обновление. Ответ 200: `run_id`, `replayed`, `total`, `counts`, `records`, `affected_employees`.
- `GET /api/imports/example` — готовый JSON-пример (обычный сеанс администратора/power_user).
- `/api/docs` — интерактивная документация схем.

Пример тела:

```json
{
  "request_id": "sap-hr-20261024-001",
  "departments": [{"external_id": "D1", "name": "Производство"}],
  "employees": [
    {"external_id": "E1", "first_name": "Анна", "last_name": "Иванова", "email": "anna@example.com", "position": "Начальник отдела", "hired_at": "2026-01-01", "department_external_id": "D1"},
    {"external_id": "E2", "first_name": "Иван", "last_name": "Петров", "email": "ivan@example.com", "position": "Начальник группы", "hired_at": "2026-01-01", "department_external_id": "D1", "manager_external_id": "E1"},
    {"external_id": "E3", "first_name": "Мария", "last_name": "Смирнова", "email": "maria@example.com", "position": "Инженер", "hired_at": "2026-01-01", "department_external_id": "D1", "team_external_id": "T1"}
  ],
  "teams": [{"external_id": "T1", "name": "Группа 1", "code": "GROUP-1", "department_external_id": "D1", "manager_external_id": "E2", "supervisor_external_id": "E1"}],
  "skills": [{"external_id": "S1", "name": "Excel", "category": "Технические"}]
}
```

Отправка, если секрет сохранён в переменной окружения `HRM_IMPORT_KEY`:

```powershell
Invoke-RestMethod -Uri 'https://hrm.example.com/api/integrations/imports' -Method Post -Headers @{ Authorization = "Bearer $env:HRM_IMPORT_KEY" } -ContentType 'application/json; charset=utf-8' -InFile './batch.json'
```

## Идентификация, обновления и повторы

`external_id` — постоянная строка до 120 символов, регистрозависимая. Она уникальна в рамках источника + типа сущности. Не используйте изменяемый email как постоянный ID. Источник нормализуется к нижнему регистру, до 40 символов: латиница, цифры, `_`, `-`, `.`. Для API источник определяется ключом, в теле его передавать нельзя.

При первом импорте существующие записи сопоставляются по email сотрудника, коду команды или названию отдела/навыка (названия без учёта регистра). Затем сохраняется связь с внешним ID. Один локальный объект не может иметь два внешних ID одного источника. Разные источники могут ссылаться на один локальный объект: согласуйте, какая система отвечает за каждое поле.

Дальнейшие обновления могут менять email, названия и коды, сохраняя локальный ID, оценки и сертификаты сотрудника. В JSON пропущенные поля не меняются, `null` очищает необязательный текст/связь. В файлах пустые ячейки означают «не менять», `#NULL` — очистку. Обязательные поля очищать нельзя. Отсутствующие в пакете записи не удаляются. Для увольнения передайте `status: "inactive"`. Шкалы навыков и оценки импорт не меняет. Аккаунты, пароли и повышенные роли через импорт не создаются. Роль обычного руководителя определяется подчинёнными; при её изменении старые сеансы аккаунта отзываются по существующим правилам.

Ссылки должны существовать в том же источнике или входить в пакет. Начальник, команда и подчинённые должны быть в одном отделе. Циклы, противоречащие связи и несколько команд у одного начальника отклоняются. Подчинённость участника определяется командой. При замене начальника достаточно передать `external_id` команды и новый `manager_external_id`: состав и вложенные команды сохраняются. Перевод в другой отдел требует согласованных связей; прежние связи переводимого сотрудника сбрасываются. Перевод руководителя с подчинёнными требует согласованного перевода/переназначения команды и работников в том же пакете.

`request_id` обязателен и уникален в рамках источника независимо от ключа. Повтор того же пакета возвращает сохранённый результат с `replayed: true`. Другой пакет с тем же ID получает 409. Бизнес-ошибки применения сохраняются в журнале; исправленный пакет отправляйте с новым ID. Структурные ошибки JSON и отказы авторизации не создают загрузку. `validate` в журнал не попадает. Для файлов ID создаётся автоматически.

Коды: 401 — неверный/истёкший/отозванный ключ; 403 — тип данных вне разрешений; 409 — конфликт ID или устаревшая проверка файла; 422 — неверные поля/ссылки/структура; 413 — превышение размера тела. Бизнес-ошибка содержит `detail` и `errors` с полями `entity`, `external_id`, `message`. Ошибки схемы возвращают стандартный массив FastAPI `detail`. После сетевого сбоя повторяйте прежние тело и request_id.

Журнал в интерфейсе показывает последние 50 загрузок, источник, канал, инициатора, время и результат. `GET /api/imports/history?limit=100` возвращает до 100 загрузок для администратора/power_user. Сырые пакеты и секреты в журнале не сохраняются.

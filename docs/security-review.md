# Проверка безопасности HRM — 7 октября 2026

## Дополнение: авторизация — 23 октября 2026

Реализованы четыре роли, серверные проверки каждого прикладного маршрута и фильтры области видимости для коллекций, счётчиков, матрицы, CSV и сводок задач. Сертификаты проверяют доступ к сотруднику до чтения или изменения файла. Роль и отдел определяются заново на каждом запросе; данные из браузера не задают права. Управление аккаунтами доступно только администратору. Для руководителя область — его отдел, включая других руководителей; для сотрудника — собственная карточка и задачи с его ID исполнителя.

Пароли хешируются scrypt с отдельной случайной солью (`N=2^14, r=8, p=5`, один из вариантов [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)). Токен сеанса — случайные 256 бит; в БД хранится только SHA-256 токена. Cookie использует HttpOnly/SameSite=Strict, а Secure включается настройкой для HTTPS; срок по умолчанию — 12 часов. Это соответствует выбранной схеме серверных сеансов из [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

Изменяющие запросы требуют `X-HRM-Request: 1` в дополнение к существующим проверкам Origin и Fetch Metadata: чужой браузерный origin не может добавить этот заголовок без разрешённого preflight. Пароли и токены не сохраняются в localStorage. При выходе, смене/сбросе пароля и обновлении доступа сеансы отзываются на сервере. Аккаунт можно отключить; собственную роль администратора снять или отключить себя через интерфейс нельзя. Первый администратор создаётся только локальной CLI-командой со случайным паролем, публичного bootstrap API нет. Действия с данными и аккаунтами записывают логин автора без паролей или токенов.

Лимитер считает неуспешные и ещё выполняющиеся попытки на IP: 10 за минуту и 30 за 15 минут. Он работает в памяти одного процесса; при нескольких процессах или публичном размещении нужен общий лимитер на прокси/в общем хранилище. Самостоятельное восстановление по email, MFA и интеграция с SSO не добавлялись. Последующие разделы отражают состояние предыдущей проверки; пункт об отсутствии авторизации ниже заменён этим дополнением.

Проверки дополнения: 18 HTTP-тестов авторизации, отдельный тест миграции заполненной БД, 19 браузерных сценариев (в том числе пять новых сценариев входа и ролей), TypeScript/Vite build, Prettier, Ruff и `alembic check`. Существующие 105 backend-тестов сохранены. На рабочей БД перед миграцией создана отдельная резервная копия; после миграции количество сотрудников, отделов, задач и сертификатов сверено, `PRAGMA foreign_key_check` не обнаружил нарушений. Пароль первого рабочего администратора не записан в исходники или документацию; тестовые аккаунты создаются только в временных тестовых БД.

Проверены исходники backend/frontend, HTTP middleware, загрузка и выдача сертификатов, запросы к БД, CSV-экспорт и зависимости. Это проверка кода и локальных сценариев; полноценный внешний пентест и антивирусный анализ файлов не выполнялись.

## Найдено и исправлено

| Проблема | Риск до изменений | Исправление и проверка |
| --- | --- | --- |
| Не проверялся Host локального API | Доступ к API через имя постороннего домена при DNS rebinding | `TrustedHostMiddleware`, точный список loopback-адресов; тесты постороннего Host и поддельного суффикса |
| CORS использовался без проверки источника запросов | Сторонняя страница могла отправить простой multipart POST; CORS ограничивал чтение ответа, но не запуск операции | Точная проверка Origin до обработчика; запрет `null`, неизвестных Origin, нескольких Origin и `Sec-Fetch-Site: cross-site` без Origin; тесты отсутствия изменений БД |
| Размер загрузки проверялся после разбора multipart | Крупное тело могло занять память или временное файловое хранилище до проверки сертификата | Общий лимит 11 МБ на поток тела через `RequestBodyLimitMiddleware`; ранняя проверка Content-Length, включая DELETE; тесты запроса без Content-Length и сохранности данных после отказа |
| Кадровые JSON/CSV-ответы не запрещали кеширование | Данные могли сохраняться в HTTP-кеше | `Cache-Control: no-store` для ответов API |
| Для файлов не задавалась CSP | Дополнительный риск активного содержимого при открытии загруженного файла в домене приложения | CSP `sandbox; default-src 'none'; frame-ancestors 'none'`, сохранён `nosniff`; браузерная проверка просмотра и скачивания |
| Путь хранилища не запрещал синтаксис Windows ADS явно | Небезопасные имена из повреждённой/изменённой БД могли содержать двоеточие | Запрет `/`, `\`, `:`, `.` и `..` до разрешения пути; сохранена проверка нахождения файла в каталоге сертификатов |

Защита Host и ограничение потока используют штатные [middleware Starlette](https://starlette.dev/middleware/). Origin проверяется отдельным ASGI middleware, до бизнес-операций. Для настройки разрешены только точные HTTP/HTTPS Origin без wildcard, пути или учётных данных. Прямые API-клиенты без браузерных заголовков продолжают работать.

## Проверенные существующие меры

- SQLAlchemy использует связанные параметры; пользовательский ввод не вставляется в SQL-текст. `%`, `_` и `\` экранируются при поиске.
- React выводит данные обычными JSX-узлами; `dangerouslySetInnerHTML` и `eval` в коде приложения не используются.
- CSV-экспорт нейтрализует формулы, начинающиеся с `=`, `+`, `-`, `@`, включая ведущие пробелы.
- Сертификаты получают UUID-имена; имя пользователя служит только именем скачивания. Проверяются расширение, сигнатура, размер и связь документа с конкретным назначением навыка.
- Изменения БД и события сохраняются одной транзакцией; конфликт записи откатывает её. Задачи дополнительно защищены версией от конкурентной перезаписи.
- Тесты и браузерные сценарии используют отдельные временные БД и каталоги media.

## Зависимости

`npm audit --json` проверил frontend: известных уязвимостей — 0. `pip-audit --path .venv/Lib/site-packages` проверил 37 установленных Python-пакетов: известных уязвимостей — 0, пропущенных пакетов — 0. Версии установленных пакетов сверены с `uv.lock`. Это результат баз advisories на дату проверки, а не гарантия отсутствия неизвестных проблем.

Starlette явно закреплён как зависимость `>=1.7,<2.0`, поскольку приложение использует его middleware ограничения тела запроса; `uv.lock` обновлён без изменения версий пакетов. Установка остаётся через `uv sync --locked` и `npm ci`.

## Оставшиеся риски

1. **Закрыто 23 октября 2026: аутентификация и права доступа.** Добавлены сеансы, роли, проверки области данных и автор изменений. Для сетевого размещения по-прежнему нужны HTTPS, Secure cookie и корректная настройка Origin/Host.
2. **Средний: нет общей квоты хранилища, ограничения частоты и числа одновременных загрузок.** Лимит одного запроса уменьшает риск, но серия допустимых запросов может заполнить диск. При сетевой эксплуатации нужны квоты и ограничения нагрузки.
3. **Средний: содержимое сертификатов не проверяется антивирусом.** Сигнатура подтверждает только начало файла; не доказывает его безопасность и полноценность. При работе с внешними документами нужен отдельный этап проверки или изолированный просмотр.
4. **Средний: SQLite и media не шифруются приложением.** Защита от других локальных пользователей зависит от прав ОС, шифрования диска и обращения с резервными копиями.
